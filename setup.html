Railway 2-Service Production Architecture

        
Create one Railway project connected to your GitHub repository and add two services from the same repo:

        

          
            

              Setting
              Service 1: kian-kernel
              Service 2: kian-miniapp
            

          
          
            

              Builder
              Auto via railpack.json (or infra/docker/Dockerfile.server)
              Nixpacks / Railpack (Node 20 + pnpm)
            

            

              Build Command
              Handled by railpack.json (cargo build --release -p kian-server)
              pnpm install --frozen-lockfile && pnpm --filter @kian/miniapp build
            

            

              Start Command
              ./bin/kian-server (port $PORT / 8088)
              pnpm --filter @kian/miniapp start
            

            

              Persistent Volume
              Required: mount at /data (KIAN_DATABASE_URL=/data/kian.sqlite)
              None (stateless)
            

            

              Healthcheck
              /api/v1/health
              /
            

          
        


        

          Critical SQLite Rule on Railway: Always attach a persistent Volume at /data on kian-kernel and keep replica count at 1. Set KIAN_TRUST_PROXY=true and KIAN_ALLOWED_ORIGINS=https://your-miniapp.up.railway.app.
        


        
Admin Operations Quick Reference (Withdrawals & Deposits)

        

          
          
# 1. List pending crypto withdrawals
curl -H "X-KIAN-Key: $KIAN_ADMIN_KEY" \
  "https://api.yourdomain.com/api/v1/admin/withdrawals?status=PENDING"

# 2. Confirm withdrawal after sending TON/USDT from your hardware wallet
curl -X POST -H "X-KIAN-Key: $KIAN_ADMIN_KEY" -H "Content-Type: application/json" \
  -d '{"txHash":"0xYOUR_ONCHAIN_TX_HASH"}' \
  "https://api.yourdomain.com/api/v1/wallet/withdrawals/wdr:ID/confirm"

# 3. Reject withdrawal (atomically refunds full Đ back to citizen)
curl -X POST -H "X-KIAN-Key: $KIAN_ADMIN_KEY" \
  "https://api.yourdomain.com/api/v1/wallet/withdrawals/wdr:ID/reject"

3. How Viral 3-Way Referral Links Work

        
Every product card in /market generates a shareable Telegram link:

        

          
          
https://t.me/<BOT_USERNAME>?startapp=prod_<PRODUCT_ID>_ref_<REFERRER_TG_ID>

        

        
    
          
  • apps/miniapp/lib/referral.ts parses start_param on launch and saves the referrer in localStorage.
    • 
          
  • When the buyer purchases the product, POST /api/v1/market/purchase locks the referrer into the escrow record.
    • 
          
  • When the buyer releases the escrow, the Rust domain kernel automatically posts a 4-leg balanced transfer splitting Platform Fee, Affiliate Commission, and Seller Payout.
